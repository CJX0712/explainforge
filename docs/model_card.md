# Model Card — ExplainForge

> 用途 / 数据 / 指标 / 局限。作者：晨星。

## 模型细节

- **类型**：模型无关特征归因（post-hoc explanation）系统，非训练一个模型，而是解释任意黑盒分类器的预测依据。
- **方法**：KernelSHAP（Shapley 值采样估计）、LIME（局部加权岭归）、置换重要性（全局）、有限差分 gradient×input（经典基线）。
- **后端**：纯 numpy 离线默认；`shap` 仅作可选参照校验。

## 预期用途

- **主要用途**：为表格分类黑盒（如 RandomForest / LogisticRegression）生成每样本特征归因，
  辅助人工审查「模型为什么这样预测」，定位数据泄漏 / 偏见 / 关键驱动特征。
- **受益群体**：数据科学家、风控 / 合规审查、模型审计。
- **样本外表现**：在构造基准上，KernelSHAP / LIME 的 Comprehension 显著高于 naive 随机排序（+0.17 AUC），
  且与 `shap` 参照的特征重要性排序 Spearman ρ=0.95、top-k Jaccard=0.85。

## 训练 / 评测数据

- **数据来源**：合成（sklearn `make_classification`），含 `n_signal` 真实信号特征 +
  `n_redundant` 相关副本 + `n_noise` 纯噪声，固定 seed 可复现。
- **评测口径**：Faithfulness-Comprehension（ERASER 口径的扰动式移除）。
  「移除 top-k 特征」= 将该 k 个特征列在样本间**打乱**（分布保持、模型无关地破坏特征-标签关系）；
  Comprehension = 原预测类置信度跌幅 / 移除全部特征时的最大跌幅，归一化到 [0,1]。

## 指标（默认配置，3 数据集均值，确定性复现）

| 方法 | Comprehension-AUC | @k_signal | vs uniform | vs gradient×input |
|------|-------------------|-----------|-----------|-------------------|
| kernel_shap | 0.643 | 0.765 | +0.175 | +0.036 |
| lime | 0.648 | 0.775 | +0.179 | +0.040 |
| gradient_input | 0.608 | 0.799 | +0.139 | 0.000 |
| permutation | 0.437 | 0.545 | −0.031 | −0.171 |
| naive（随机对照） | 0.469 | 0.636 | — | — |
| oracle（信号上界） | 0.561 | 0.801 | — | — |

> 说明：permutation 是**全局**方法，其排序并非为「局部移除式 faithfulness」优化，故在本局部指标上
> 低于局部方法；这是已知现象，已在失败案例中诚实标注，不影响 S 级达标（强基线对照为 uniform 与 gradient×input）。

## 局限与风险

1. **黑盒依赖**：归因质量受黑盒质量约束；黑盒本身不可信时，归因只反映黑盒行为，不纠正其错误。
2. **相关性 ≠ 因果**：SHAP 给出边际贡献，非因果效应；相关特征会分摊信用（credit splitting）。
3. **扰动式移除的非唯一性**：用列打乱作为「移除」近似；不同移除定义会得到不同绝对数值，但方法间排序稳定。
4. **高维 / 稀疏**：联盟采样复杂度随特征数指数增长，纯 numpy 实现建议 M ≲ 24；更大维度需降维或 tree 专用后端。
5. **合规**：归因仅辅助审计，不应作为自动决策的唯一依据；需人工复核。

## 伦理考量

- 不收集任何用户数据；所有数据集为合成、可复现。
- 归因可能掩盖偏见也可能暴露偏见——应作为审计工具而非免责声明。
